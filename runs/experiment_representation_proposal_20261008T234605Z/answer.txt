## Candidate: event-graph counterfactual transport (EGCT)

**Claim to test:** In contact-rich physics tasks, learning a source-to-target transport of *event-graph changes* can construct new event-triggered intervention programs that solve held-out scenes more efficiently than an ordinary optimizer initialized with the identical source proposal prior.

This is deliberately not a claim that the existing result demonstrates such an operation. The existing result demonstrates a useful placement prior, and ordinary GP with that prior already reaches 8/8. EGCT is a proposed operation whose required distinction is that source learning must change the **program topology** of target experiments—not merely their ranking or initial placement.

### Learned transformation

Represent each trial by

\[
\tau=(a,G,Y),
\]

where \(a=(x,y,r)\) is the initial placement, \(G\) is the ordered contact/event graph, and \(Y\) contains continuous event attributes such as contact times, positions, velocities, and object identities.

A source trial pair provides a local intervention transition

\[
(G,Y,a)\xrightarrow{p}(G',Y'),
\]

where \(p\) is a native experiment program. A program may contain:

```text
initial placement
wait until event predicate q
apply force / impulse / add / remove / set intervention
continue
```

EGCT learns two objects from source transitions:

1. an event-conditioned transport map

\[
F_\theta(G,Y,p)
\rightarrow
\bigl(\hat z,\hat \ell\bigr),
\]

where \(\hat z\) predicts continuous event attributes and \(\hat\ell_e\) is a relaxed activation logit for each possible event-graph edge \(e\);

2. a distribution of graph edits

\[
D_\theta(\Delta G\mid G),
\]

learned from observed source graph differences, rather than supplied as a fixed catalog. An edit can create, delete, reorder, or delay an event edge.

For a failed target trial with graph \(G_t\), EGCT samples or selects a source-supported edit \(\Delta G\), then solves for a **new program**:

\[
p^\star =
\arg\min_{p\in\mathcal P}
\underbrace{
\left\|
\operatorname{softgraph}(F_\theta(G_t,Y_t,p))
-
\operatorname{softgraph}(G_t\oplus\Delta G)
\right\|^2_W
}_{\text{counterfactual graph target}}
+
\lambda\, C(p)
+
\mu\, R_\theta(p).
\]

Here \(C\) charges every physical intervention, including branch-triggered actions, and \(R_\theta\) penalizes extrapolation outside source-supported event contexts. The important operation is the inverse construction of \(p^\star\): the target experiment is not selected from a menu of initial placements or supplied programs.

The source output therefore changes which target experiments can be constructed. For example, if source data show that delaying a first contact tends to expose a second collision, EGCT can produce:

```text
place ball at a newly solved position
wait for first-contact predicate
apply an impulse with newly solved magnitude and direction
continue
```

The trigger, timing, intervention parameters, and resulting event topology are all generated by the transport solve. They are not copied as a source skill or ranked from a fixed proposal set.

To avoid reviving the rejected equal-weight secant estimator, the transport should be fitted branch-conditionally with robust weighted likelihood and a discrete event-activation loss:

\[
\mathcal L(\theta)=
\sum_i w_i
\left\|Y_i'-\hat Y_i'\right\|^2
+
\beta\operatorname{BCE}(G_i',\hat G_i')
+
\gamma\,\Omega(\theta),
\]

where \(w_i\) depends on event rarity and local branch density, not equal weighting of all secants. The discrete graph term is essential: a model that only predicts continuous event displacement is not EGCT.

### Executable pseudocode

```python
def learn_egct(source_trials):
    # Each trial has: initial action, event graph, continuous event data,
    # and optionally a native intervention program.
    transitions = []
    edit_counts = {}

    for old, new in paired_or_local_counterfactuals(source_trials):
        G0, Y0, a0 = old.graph, old.events, old.action
        G1, Y1, p1 = new.graph, new.events, new.program

        edit = graph_diff(G0, G1)          # edge create/delete/reorder/delay
        ctx = graph_context(G0, Y0, a0)
        transitions.append((ctx, p1, G1, Y1, edit))
        edit_counts[(canonical_graph_type(G0), edit)] = \
            edit_counts.get((canonical_graph_type(G0), edit), 0) + 1

    F = fit_branch_conditional_transport(
        [(ctx, p, G1, Y1) for ctx, p, G1, Y1, edit in transitions],
        loss="robust_continuous_plus_event_activation"
    )
    D = normalize_edit_counts(edit_counts)
    return F, D


def egct_action(scene, history, F, D, budget):
    trial = native_run(scene, history.initial_program)
    best = trial

    while trial.queries < budget:
        ctx = graph_context(trial.graph, trial.events, trial.action)

        candidate_edits = propose_edits(
            D,
            current_graph=trial.graph,
            exclude_seen=True
        )

        candidates = []
        for edit in candidate_edits:
            target_graph = graph_compose(trial.graph, edit)

            # Program variables include placement and optional branch actions.
            p = solve_inverse_program(
                lambda program: F.predict(ctx, program),
                desired_graph=target_graph,
                cost=native_trial_cost,
                extrapolation_penalty=F.extrapolation_penalty,
                constraints={
                    "native_primitives_only": True,
                    "trigger_predicates_from_observed_events": True
                }
            )

            if p is not None:
                candidates.append(p)

        if not candidates:
            break

        p = choose_by_predicted_goal_gain_and_cost(candidates, F, trial)
        trial = native_run(scene, p)
        F.update(ctx, p, trial.graph, trial.events)

        if trial.score > best.score:
            best = trial

    return best
```

`solve_inverse_program` is a small CPU nonlinear search over continuous placement/intervention parameters and discrete trigger locations. It is not a search over a fixed program catalog; the program skeleton is obtained from the predicted graph edit, while its parameters are solved continuously.

### Smallest decisive native experiment

Use **eight preregistered fresh Interphyre scenes**, balanced across two task families in which success can require a post-contact consequence. Do not use the already solved eight scenes. Every method receives the same query budget and native intervention primitives; all physical trials, including failed branch interventions, count.

Compare:

1. **Matched-prior GP:** the existing source-generated proposal prior plus ordinary GP optimization.
2. **EGCT:** initialized with exactly that same proposal prior, but allowed to construct event-triggered programs through the transport solve.
3. **No-transport ablation:** same graph representation and branch-program search, but source transport removed; branch parameters are optimized from target data only.
4. **Fixed-prior placement control:** source prior with no interventions, to establish the current baseline.

The decisive precondition is that at least four scenes contain a useful intervention topology absent from the initial-placement proposal support. This must be determined from scene construction, not after inspecting outcomes. The primary endpoint is success rate at a fixed physical-trial budget; the secondary endpoint is success per physical trial. Two mechanistic checks are required:

- EGCT must emit at least one program with a trigger/intervention topology not present in the initial source proposal set.
- Replacing its generated program with the matched-prior GP’s best initial-placement action must remove the advantage.

A positive result is not “EGCT ranked the same placements better.” It requires that the newly constructed branch program changes the reachable experiment class and improves held-out performance against the identical prior.

### Strongest reduction to an ordinary method

The strongest reduction is exact:

- If interventions are disallowed, or every branch program is reduced to an initial placement, EGCT becomes ordinary optimization under a reparameterized action coordinate.
- If the event graph is fixed and \(F_\theta\) predicts only a scalar score, the objective is an ordinary GP/acquisition problem with a learned mean or kernel.
- If every learned graph edit corresponds to an existing program in a finite menu, EGCT reduces to menu ranking or workflow/program search.
- If \(F_\theta\) is replaced by a fixed transition model, the operation reduces to model-based planning with an event constraint.

Therefore the proposed distinction is defensible only in the remaining regime: **source learning must infer graph-changing intervention transformations and continuously synthesize previously unavailable native programs**. The current evidence does not establish that regime; it only motivates testing it.
