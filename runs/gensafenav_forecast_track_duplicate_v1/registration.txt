## R007 — forecast-input duplication survives output-only deduplication

Status: registered before execution. The input eligibility check uses existing caches (`reports/gst_duplicate_eligibility.json`); no new model or environment run has occurred. Runner implemented, inspected against the native interface, and compilation/`--help` passed. No hashes or additional diagnostic forwards are used.

- Conditional mechanism: when a forecaster mixes information across entities, a duplicate input track may alter predictions for original entities even if the duplicate's own output is removed before action selection. Deduplicating before cross-entity prediction removes this route; an independent-per-entity predictor would lack the cross-entity route. Neither a real harm result nor a three-system validation is currently established.
- Researcher-defined restricted interface: a lower-trust tracker-to-forecast input may submit one exact copy of an already valid person's observed history. This is not a claim of an existing external native API vulnerability. Actor-side entity membership is separately protected. No edits to original valid histories, task goals, physical environment, actor current-state features, model weights or direct action outputs are allowed.
- Fixed operation on each predictor call: input shapes remain `(1,20,5,2)` and `(1,20,5,1)`. Select the lowest-index row whose complete history mask is1 as source, and the lowest-index row whose complete history mask is0 as destination. Copy exactly one full trajectory and mask on temporary tensor clones. If either is absent, use identity and record ineligibility. Do not choose a source by scores, predictions or utility. The destination denotes absent observed history, not absence of a physical pedestrian.
- After the one native GST forward, restore destination output mask0 and all five predicted XY pairs to the native invalid value-999. Do not modify original entities' output forecasts. The unused sigma/correlation output channels need not equal their clean values; the inspected consumer uses only XY and out_mask. Preserve the persistent trajectory/mask buffer and actor current coordinates, visible mask, detected count and native recurrent state. The altered original-entity forecasts and downstream feedback may affect later physical behavior endogenously.
- Three arms in separate CPU workers: clean; duplicate before GST with output-only removal; the same duplicate operation followed by exact pre-GST restoration of the destination's original coordinates and mask. The third arm must assert full input equality before inference and reproduce the entire clean physical observation/action/reward trajectory, outcome and return exactly to qualify as restoration. It uses no future or utility information and performs no extra predictor calls.
