## R006 — semantic-preserving person-row ordering at a forecast consumer

Status: registered before execution; runner implemented and Python compilation/`--help` passed without loading models. No new navigation episode has been launched. This is an expected no-effect structural control, not an established attack or a substitute for the required cross-system mechanism.

- Conditional mechanism hypothesis: a learned consumer that treats an unordered set of complete person forecasts as slot-specific inputs could change real control under a representation-only ordering change. A permutation-invariant consumer lacks this route. Inspection of GenSafeNav predicts the latter: shared attention and symmetric pooling, with persistent memory after aggregation. Basic permutation sensitivity/invariance is not claimed novel.
- Declared researcher boundary: permit only reversing the visible prefix of person rows presented to the actor after the native forecast/feedback update. Each person's12 position/forecast coordinates and5 conformity features move together. Do not change simulator objects, identities, histories, forecast numbers, uncertainty numbers, physical observations, robot goal, padding suffix or visibility count. There is no claimed native external attacker permission; arbitrary entity mismatches are forbidden.
- Assets and consumer: reuse `probe_gensafenav_feedback_selection.run`, saved Ours_GST actor05207 and GST epoch100 checkpoints, existing case0/seed42 CPU configuration. The inherited test protocol sets conformity/cost noise to zero and collision penalty to-20, uses deterministic actor actions and a CPU-only AddBias device bridge. Preserve its known feedback indexing defect; this experiment neither repairs nor exploits that defect.
- First test: two complete native episodes, original ordering and fixed reverse-visible ordering, identical initialization/random seeds. Retain each arm's own native aggregated recurrent state; do not overwrite hidden state or permute padding into visibility. Record original and presented feature rows with inverse-permutation equality checks; no additional GST forecasts, no fitted decoder or shadow actor selection. Native environment termination, at most202 loop iterations per arm.
- Primary physical outcomes: actual environment return, terminal success/collision/timeout and executed steps. Report actual cost, clearance and action differences as diagnostics when recorded by the existing harness. Numerical no-effect criterion: identical terminal category and step count, absolute return difference<=1e-4, and maximum paired action-coordinate difference<=1e-5. Failing this tolerance check alone is not an attack-success result.
- Material-loss gate, fixed before outcomes: reversal introduces a collision, removes baseline success, or lowers real return by at least0.05*max(1,abs(original return)). A single reused case is descriptive; no ASR/confidence interval/population robustness claim. Even a positive result needs numerical and implementation explanations excluded before a security claim.
- Runtime: `.venv-gensafenav/bin/python scripts/run_gensafenav_person_row_permutation.py --run`; CPU only, total hard wall300s, no retries, training/API/network or seed/permutation/tolerance search. Preserve partial records if interrupted. The runner must enforce complete episodes and disclose any inability to compare traces, not silently count missing outcomes as no harm.
- Difference from closed work: R001 mismatched action/forecast identities; R006 preserves every person/trajectory/uncertainty association and changes only presentation order. Prior GenSafeNav gates changed uncertainty magnitudes or feedback timing/selection; neither intervention is allowed here. R005 changed learned dynamics in proposal and evaluation consumers; R006 freezes predictors, forecasts and actor weights. No score-temperature experiment follows R005.
- Stop rule: no material loss closes this fixed order-only intervention without seeking another permutation, task or seed. Approximate invariance is a local structural control, not three-system security validation; exact mathematical invariance must not be inferred solely from a single numerical episode.
